## 联机（P2）

```bash
node server/index.mjs          # 或 npm run serve，默认 8787
# 打开 http://127.0.0.1:8787/online.html
```

一个进程同时做三件事：静态站点、WebSocket 房间服务、规则裁决。**零 npm 依赖**（连 WebSocket 都是手写的 `server/ws.mjs`，200 行），所以部署就是打一个 node 镜像。

### 房间流程

1. 房主建房 → 得到 6 位房号；
2. 朋友用「房号 / 邀请链接 `#123456`」进入；
3. 房主选人数：2 / 3 / 4 混战 / 2v2 / 3v3 / 4v4；
4. 空位点「补人机」，任意座位可改势力归属（每势力 1–2 人）；
5. 点开始 → 座位锁定，不能再改。

### 一回合的时序（服务端权威）

```
拍卖 15s（仅第 5/10/15… 回合，是该回合的第一个环节；先公示后出价，整点出价）
   → 天机判定（R42 后已无天机窗口：天机门人身世删除，回到纯自然概率）
   → 出牌 45s（同时暗选；超时默认「进阶防御」，能量不够则「普通防御」）
   → 追问 12s（只有需要选目标/选牌的人；服务端先干跑收集 prompt 再问）
   → 结算广播 → 弃牌判断 20s（手牌超上限的人挑牌弃掉）
   → 展示 3.5s → 下一回合 / 局末 20s
```

「追问」这一环是这次新增的关键：`engine.collectPrompts()` 克隆一份状态、用空答案干跑，
把"要问谁什么"收集出来（随机序列一起复制，所以 prompt id 两次一致），问完再带答案真跑。
**引擎仍然是纯函数**，没有改成协程，也没有给每张牌写预检。

### 客户端只发意图

消息很小：`play / tianji / answers / bid / next / take / addAI / faction / config / start`。
收到的永远是 `viewFor(m, seat)` 的投影 —— 别人的手牌在结构上就不存在，随机种子永不下发。
**前端不 import 引擎**（只 import 卡牌名表用于显示），所以不可能出现"两边算法则"。

### 掉线与退出

- 掉线：座位保留，超时按默认动作继续；**90 秒**没回来转人机托管。
- 刷新页面：`localStorage` 里的 token 会自动 `resume` 回原座位（同一浏览器）。
- 主动退出：回大厅，座位让出。

### 验证

```bash
node server/e2e.mjs 4 2      # 真 WebSocket 客户端跑完整场（2v2）
XD_FAST=1 node server/e2e.mjs 8 2   # 压缩过场动画，8 人满编
node tools/web_e2e.mjs 4 2   # 真 Chrome + 4 个 iframe 加载真页面，跑完整场
node tools/shot.mjs          # 出大厅/对局/手机三张截图
```

`web_e2e` 这一层专门抓"Node 里跑得通、浏览器里白屏"的问题 —— 它已经抓到过三次：

1. **多标签抢座**：`localStorage` 是同源的，新开的第二个标签页会自动 `resume`，把第一个标签的座位顶掉，
   而第一页已经不连接了却还显示旧界面（表现为"突然卡住不动"）。
   修法：客户端只在 `#房号` 与本地记录一致时才自动续座；服务端在旧连接仍存活时拒绝 `resume`。
2. **2v2 开局失败**：`validConfig` 原来手写枚举，漏了"2 势力 × 2 人 = 4 人"。改成按 `势力数×人数` 计算。
3. **自爆第 1 回合能点**：视图与引擎口径不一致（引擎跳过，视图仍列出）。视图侧补齐同一条件。

## 三条设计约束

1. **引擎不认识任何牌名。** `src/` 目录里 grep 中文牌名应为 0 命中。卡牌元信息全部在 `data/cards.json`，效果全部在 `data/effects.json` 的原子列表里。
2. **所有数值走定点数。** 1 单位 = 0.5 点（`src/units.mjs`），避免 0.5 血的浮点误差。
3. **所有随机走种子 RNG。** `src/rng.mjs`，种子落在对局记录里，一局可完整复现 —— 这是回放、AI 推演、平衡复现三者共用的地基。

## prompt 系统怎么工作

引擎是纯函数，**不阻塞**。结算中途需要的选择，全部走 `src/prompts.mjs` 的答案表：

```js
resolveTurn(m, actions, { answers: { 0: { ban_0: 2 } } })   // seat 0 把符咒指向 seat 2
```

缺答案时走兜底（R18 最保守项），所以任何情况下都能算完。线上做法是：揭示后服务端再发一次「补充选择」（短倒计时），收齐再调 `resolveTurn`——同一套接口，离线 AI 只是在决策时一次预填。

五种提示正好覆盖全部二次互动：`target` 选目标 · `card` 选牌 · `allocate` 分配数值 · `branch` 二选一 · `subgame` 同时博弈。处理器按**原子名**分四个挂点执行（不认牌名）：

| 挂点 | 时机 | 典型原子 |
| --- | --- | --- |
| PRE | 算数值之前 | `banCard` `banAllEnemies` `lockSpirit` |
| VALUE | 算胜者线之前 | `perHitAtkUp` `allocate` `copyAction` |
| COMBAT | 命中之后 | `energySteal` |
| POST | 回合末 / 博弈 | `subGame` `soulSwap` `stealCard` `banSet` `revive` `swapActions` `tallPoppy` `link` `credit` |

## 行动层：5 个阶段位，不往结算里堆 if

这 8 张牌的共同点是"它们不属于结算"，所以各自挂在不同的**阶段**上：

| 阶段 | 参数位 | 谁在用 |
| --- | --- | --- |
| 开局特别阶段 | `startRound(m, { setup })` | 官宦子弟：从本局术池挑 1 张临时术（一场 4 局 = 4 次） |
| ~~天机前窗口（5 秒）~~ | —— | **R42 已作废**：天机门人身世删除，不再有这个挂点 |
| 出牌前非出牌操作 | `resolveTurn(m, acts, { freeOps })` | 杏林（2 能量换治疗牌）、平民（1 血 ↔ 2 能量），不计入本回合出牌 |
| 出牌时参数 | `action.craft = { delta, patch }` | 匠作之家：±N 数值；超防花 1 能量补掉"被普攻破"的缺点 |
| 揭示后反制窗口 | `resolveTurn(m, acts, { reactions })` | 无懈可击（免疫本回合道牌）、替罪（免疫 + 转出） |
| 改写后可用 | `forcedAttackBy` 标记 | 借刀杀人：强制目标下回合必须**打出攻击**；不打或打不出 → 扣 1 血；该次攻击**对施术者及其队友无效，但对被强制者的队友照常生效**（全作唯一的友军伤害例外） |

这个划分的好处是：**下一个人身世或道牌进来时，先问"它属于哪个阶段"，答案会直接指向一个已有的参数位**，而不是又一层 `if`。

## 已知偏差（刻意为之，等确认）

- **道牌未进入 AI 决策**：AI 目前不买牌、不用牌。道牌相关平衡数据为空。
- **五雷正法**用不动点逼近（按"能打中几个人"反推 +1 次数），与"每实际造成一次伤害 +1"在极端情况下会有一次误差。
- **明镜 / 水中捞月 / 镜花水月**：复制后把牌放进 `tempCards` 供下回合使用；"被打破则无法复制"未单独判定（防御被破时本就扣血，复制仍生效）。
- **引雷**按 R33 改判为「本回合所有攻击数值 +3」，不是直接 3 点伤害（原先实现错了，`卡牌.xlsx` 的文案也同步改了）。改判后 2 回合内结束的局从 1.1% 降到 0.13%，局均回合数从 20.6 回升到 21.9 —— 清场问题自然消失，因为抬高了攻击却没抬高任何人的墙。
- **替罪**是近似实现：免疫本回合道牌效果，并折算为对目标 1 点伤害。精确"转移原效果"需要每个处理器支持改绑目标，等确认后再做。
- **命运乖离**加了两条工程护栏：互换后血量最低 0.5；且只在第 5 回合后进池。否则局初触发会让整局 1 回合结束（实测确实如此）。
- **自爆**使用频次偏高（约 2.6 次/场），因为 L1 在 1 血时的随机噪声会选中它。属于 AI 性格问题，不是规则问题。

## 道牌与拍卖

```js
const offer = peekAuction(m);                    // 先公示，后出价
const bids  = { 0: bidFor(m, p0, offer), ... };  // 整数能量，上限 = 当前能量
auctionIfDue(m, { offerId: offer, bids });
```

拍卖按 7.7：最高价唯一 → 成交；**并列 ≥3 → 各付各价各得一张**；**并列 ≤2 或全场 0 → 流拍**；神装成交可立即装备，不占手牌位。

AI 的道牌估值只看「类别 + 原子」：神装 2.0–2.6（加攻/减伤更高）、神策 2.2、神通 1.5；出价再从可支配能量里留出攻击用的余量。**这不是精确收益模型**，所以报告里的成交价反映的是"AI 认为值多少"。

## 同盟模式：把"势力"变成一等公民

以前"1 人 = 1 势力"是巧合，现在是显式结构：

```js
m.factions = [{ id, members: [seat, ...], sets: [], score }]
```

五处从"按人"改成"按势力"：

| 原 | 现 |
| --- | --- |
| 每人挑 1 套术集 | **每势力挑 1 套**，写进 `faction.sets`，再同步给所有成员 |
| 个人存活时长 | **最后一名成员被淘汰的回合数** |
| 个人积分 | 势力共享，同队同分（9.4） |
| 击杀者独得能量 | **伤害来源所在势力的全体成员**均分（4.5 + 同盟条款） |
| 局末胜者 +1 道牌 | 发给**每名存活成员** |

跑法：`node cli/selfplay.mjs --matches 500 --players 4 --per 2`（2v2）；`--players 6 --per 2`（3v3）。

### 一个真实的规则冲突（待裁定）

**"队内不互相伤害" 与 "判定失败" 打架。** 胜负线是全场唯一的，所以 2v2 里队友打出更高的数值，你一样会"判定失败"扣 1 血——这不是被打中，是被判负。

实测数据能说明它有多常见：

| 模式 | 命中 : 判定失败 |
| --- | --- |
| 4 人个人战 | 8.3 : 1 |
| 2v2 同盟 | **5.4 : 1** |

也就是说同盟局里，每 5 次命中就伴随 1 次"被判负"，其中相当一部分来自队友。当前实现**不豁免队友**（严格按 4.2）；要不要改成"只对敌方的胜者线判定失败"，是一个会影响同盟强度的开关。

## 视角投影：能发出去的那一份

```js
import { viewFor, auditView } from "./src/view.mjs";
const v = viewFor(m, seat, { events });   // seat = -1 即观战
if (auditView(v, m, seat).length) throw new Error("投影泄漏");
```

```bash
npm run view        # 打印"座位 0 的客户端会收到什么"
```

投影的三条硬规则：

| 内容 | 处理 |
| --- | --- |
| 自己的手牌、临时术 | `me.hand` / `me.tempCards` |
| 别人的手牌 | 只给 `handCount`（数字），结构上就没有 `hand` 字段 |
| 血量/能量/术集/装备/身世 | 公开 |
| **随机种子** | **永不下发**——知道种子就能推算天机与牌堆 |
| 可出牌与费用 | 服务端算好再下发，客户端不复刻规则 |

`auditView` 是结构性自检（不是字符串搜索）：它检查公开区有没有多出 `hand` 字段、`me.hand` 是否只有自己的牌、有没有 `seed/daoDeck/dmgLog` 这类内部字段。**建议每次下发前都跑一遍**——这类泄漏一旦上线就是“改个 JS 变量看全场手牌”。

实测：4 人的玩家区从 2168 字节压到 811 字节；观战视角（seat = -1）连 `me` 都没有。

### 牌桌布局规则

座位不按座位号排，按**势力**排边：自己在南，其余势力按序号顺次坐剩下的边。

| 势力数 | 占用的边 |
| --- | --- |
| 2 | 南 / 北（正对） |
| 3 | 南 / 西 / 东（北边空出来） |
| 4 | 南 / 西 / 北 / 东 |

同一势力的 2 个人并排在同一边（8 人局）。每个座位靠桌心的一侧有出牌槽：
结算后把该玩家打出的牌亮在那里约 4 秒，暗选阶段只显示自己那张。

中央是「天机坛」：本回合天机（点开看全文）+ **仍在生效的遗留效果**（攻击加成、返璞归真…带剩余回合）
+ 本局争夺的术集。右侧事件面板可以收起，收起后主画面自动变宽。
